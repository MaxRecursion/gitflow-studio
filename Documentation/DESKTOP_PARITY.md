# GitHub Desktop workflow evidence ledger

## Identity, method, and claim boundary

Reference: GitHub Desktop source at commit [`c3a5c51ea7bccd98f0d32dd2f6db531296d8215d`](https://github.com/desktop/desktop/tree/c3a5c51ea7bccd98f0d32dd2f6db531296d8215d), inspected from a separate read-only checkout. This ledger follows feature entry points through their Git service calls, then compares them with the independently written Swift implementation. No Desktop source, branding, or artwork is incorporated in GitFlow Studio.

The requested REA workflow was routed using the official [`reverse-engineer-anything` skill, version 58, at revision `22e5aa97af8d726400f3f932cae10e0083412038`](https://github.com/morluto/rea/blob/22e5aa97af8d726400f3f932cae10e0083412038/.agents/skills/reverse-engineer-anything/SKILL.md). Its source-analysis rule directs complete-source investigations to ordinary repository tools and excludes unnecessary REA provider/readiness commands. Therefore the evidence here is pinned **source evidence**, not decompilation or observation of a shipped Desktop binary. Feature flags, server state, and runtime-dependent behavior are not inferred merely from source presence. Desktop worktree menu entries, for example, are guarded by `enableWorktreeSupport()`.

Statuses describe GitFlow Studio: **Verified (T)** means a named automated test exercises the stated service behavior; **Verified (G)** means a recorded native-app GUI smoke test; **Implemented (I)** means a connected code path exists but that interaction has not been individually verified; **Partial (P)** identifies a working subset with the remaining difference stated; **Missing (M)** means no implementation was found in the inspected app/core sources. A row can have more than one status. None means complete Desktop parity or production certification.

Evidence boundary: Desktop's [native menu definitions][menu], corresponding `app/src/ui` feature components, and `app/src/lib/git` operations were inspected. GitFlow Studio's `Sources/GitCore`, `Sources/GitFlowStudio`, and `Tests/GitCoreTests` were compared. The ledger covers the requested Git workflows and material adjacent Desktop features; it is not an exhaustive inventory of every Desktop preference, integration, experiment, or platform behavior.

All 54 pinned Desktop path links in this document were checked against the actual source checkout; every referenced file or directory exists at the recorded revision. Runtime observations are recorded separately in [GUI_VERIFICATION.md](GUI_VERIFICATION.md).

| Choose or edit a resolution | Desktop [stage.ts][stage] and [checkout.ts][checkout] apply manual version choices, with the surrounding UI/store managing conflict workflow. | **T, G; independent product extension:** Studio has a native current/incoming/result editor, optional ancestor, local region current/incoming/both/reset/manual choices, decision undo, and TextKit editing. `mergeDecisionsKeepUnrelatedManualEdits` and `multipleConflictRegionsAndSpanningManualEdits` verify manual-edit preservation. |
| Word-level comparison | Desktop [diff/changed-range.ts][changed-range] and diff rendering calculate/display changed ranges. | **T, G, P:** `WordDifference` computes lexical changes only for the selected conflict, at most 100 KB and 2,000 tokens per side. UTF-16 ranges and repeated-fragment ambiguity are tested by `wordChangesAreBoundedAndRespectUTF16`. Source highlights were visually inspected after fixing ruler clipping. Oversized comparisons are omitted; ambiguous source mappings are not highlighted. General working-diff word highlighting and semantic code analysis are absent. |
| Non-text resolutions | Desktop conflict stages/manual resolution helpers and diff type handling distinguish special files. | **T, P:** whole-version bytes, deletion and symlinks preserve the selected file type; CRLF/no-final-newline cases are tested. | Stage/continue/abort | [commit.ts][commit], [merge.ts][merge], [rebase.ts][rebase], [cherry-pick.ts][cherry-pick], [revert.ts][revert] use Git operation state. | **T, G:** expected index/workfile validation, confirmed write+stage, explicit native continuation/abort and refresh. GUI test changed timeout `15` to `45`, navigated away/back, staged the result, and continued the merge; Git verified clean status, exact content, and a two-parent merge commit. |
| Draft lifecycle | Source-driven UI state is distinct from Git's persisted working/index state. | **G, P:** `StudioModel` retains one conflict model across workspace navigation. Repository switch, window close, and app quit guard unsaved conflict drafts and commit messages; running Git operations must finish or be cancelled before closing. Command-W/Command-Q prompts were exercised, and Keep Working retained the draft. Existing working edits can be previewed/adopted. GUI restart recovery and multi-file caching still need coverage. |
| Native menus/search/accessibility | [menu][menu] defines Desktop shortcuts/actions and UI components expose keyboard/accessibility behavior. | **I, P:** SwiftUI menus, native controls, dialogs, TextKit find/undo, keyboard shortcuts, multiple windows and a small command palette are implemented. Full command coverage, VoiceOver/keyboard-only audit, native UI automation, and notification flows remain. |
| Performance and resilience | Desktop uses paginated/history and diff infrastructure plus process progress/error handling. | **T, P:** Studio bounds capture/diffs, serializes mutations by canonical common Git directory, coalesces status, uses FSEvents, and paginates history. `linkedWorktreesAndSymlinkAliasesShareMutationGate` verifies shared serialization, while `separateRepositoriesDoNotShareMutationGate` verifies independent queues. Cancellation tests cover queued waiters. 67 tests pass in the recorded run. [PERFORMANCE.md](../PERFORMANCE.md) separates actual measurements from unmeasured targets; no comparative Desktop benchmark was conducted. |

## Local verification record and next evidence

The native GUI tests used disposable fixture repositories. The manually edited merge produced commit `0b85983ac7242a30a28b459fe3a864d6c36ddebd` with two parents, a clean index/worktree, and `Settings.swift` containing timeout `45`, retries `5`, and environment `development`. A subsequent incoming-choice merge produced `f06365b37dc3de34793cd6f547a2308dd50160f4`, with two parents and timeout `60`. A native identity/ignore/coauthor workflow produced `fd44193cf7ce6c7f059c26a62f808ae64a1a7979`; worktree creation and unsaved-draft close/quit guards were also exercised. See [GUI_VERIFICATION.md](GUI_VERIFICATION.md) for exact observations and remaining gaps. These are functional observations, not reproducible XCUITest artifacts.

The recorded automated run passed **67 tests**. Test sources are [CoreTests](../Tests/GitCoreTests/CoreTests.swift), [ConflictTests](../Tests/GitCoreTests/ConflictTests.swift), [OperationsTests](../Tests/GitCoreTests/OperationsTests.swift), [HardeningTests](../Tests/GitCoreTests/HardeningTests.swift), [WorkspaceTests](../Tests/GitCoreTests/WorkspaceTests.swift), [WordDifferenceTests](../Tests/GitCoreTests/WordDifferenceTests.swift), [LineStagingTests](../Tests/GitCoreTests/LineStagingTests.swift), and [PathEncodingTests](../Tests/GitCoreTests/PathEncodingTests.swift). Full Xcode/Instruments, macOS 14 runtime, Intel runtime, live-host authentication, and production signing/notarization have not been verified.

Next parity work should prioritize repository safety regression tests, missing-final-newline selection and richer diffs, specialized complex conflicts, and complete native keyboard/accessibility coverage before expanding risky history rewrites or hosting integration. UI paths without a recorded native smoke test still need one; a source path alone does not upgrade their status to GUI-verified.
